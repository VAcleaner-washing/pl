# VAcleaner v4.1.57 — ANALYTICS TRUTH & STABILITY

Дата: 27.08.2026  
Build: 4157

## Що виправлено

### 1. RETURN / «сплячі клієнти» більше не зачіпають нову заявку
- `pending` тепер вважається активною заявкою в аналітиці, SMS-аудиторії та RETURN/PERSONAL promo eligibility.
- Клієнт, який уже залишив нову заявку, не потрапляє в «Кого повертати першими» і не має отримати RETURN-пропозицію як «сплячий».
- Inventory reservation не змінювалась: `pending` не резервує техніку сам по собі.

### 2. «Попит за днями видачі» тепер показує реальний попит
- Основний попит: `confirmed + issued + completed` за `start_date`.
- `pending + waiting_payment` показуються окремо як потенційний попит.
- Блок більше не чекає завершення оренди, щоб показати вже підтверджене навантаження на день.

### 3. Воронка більше не занижує конверсію активними бронюваннями
- Фінальний % рахується серед закритих заявок: `completed / (completed + cancelled/declined)`.
- Окремо видно: «Завершено», «В роботі», «Втрачено».
- Накопичувальні етапи воронки збережені.

### 4. Неузгоджена виручка більше не маскується під оренду
- Якщо `total` не збігається із сумою складових, різниця не додається тихо до «Оренди».
- Аналітика показує окреме попередження «Неузгоджено в даних» із сумою різниці.
- Це перетворює аналітику на контроль якості фінансових даних, а не лише красиву візуалізацію.

### 5. Фінансовий період використовує фактичне завершення
- Для завершених оренд `completed_at` має пріоритет над плановим `return_date`.
- `return_date` лишається fallback для старої історії, де фактичний timestamp відсутній.
- Та сама логіка застосована до останньої завершеної оренди в RETURN/SMS eligibility.

### 6. Джерела заявок стали управлінською метрикою
- Для Instagram / сайт / телефон / інше показується `% завершено` разом із кількістю заявок і поточним результатом.
- «Сплячі» та «Кого повертати першими» мають явну позначку «станом на сьогодні», бо не залежать від глобального фільтра періоду.

### 7. Стабільність джерел даних і релізів
- `config/vacleaner.json` збережено як єдине джерело цін, доставки, слотів, залогів і каталогу; генератор синхронізує browser core та backend configs через один source hash.
- `sync-static-copy.mjs` більше не відкочує актуальні SEO-description шести ключових сторінок на старі формулювання.
- Історичні one-off patch-скрипти v4.1.47–v4.1.56 більше не програються заново при кожному `stamp`; вони залишені лише для аудиту й regression tests. У релізному pipeline лишилися deterministic normalizers та config-driven generators.
- Контрольний прогін показав, що спрощений `stamp` дає байт-у-байт той самий релізний результат, що й старий ланцюг, але без проміжного переписування контенту.
- Додано регресійний контракт v4.1.57 на analytics truth, RETURN safety, source-of-truth hash, спрощений stamp, SEO copy та збереження task-first бронювання.
