# VAcleaner v3.0.6 — PWA build stamp fix

## Основа
Реліз створено тільки поверх актуальної повної збірки `VAcleaner v3.0.5 — DEPOSIT COPY FIX`.

## Причина проблеми
`scripts/stamp-build.mjs` оновлював версію кешу та ресурсів у `admin/sw.js`, але не оновлював query-параметр у реєстрації Service Worker усередині `assets/admin-v250.js`.

Через це в релізі v3.0.5 одночасно були:

- кеш Service Worker `vacleaner-manager-3005`;
- ресурси Service Worker з `?v=3005`;
- реєстрація Service Worker `/admin/sw.js?v=3001`.

Поточний `npm run check` перевіряв кеш Service Worker, але не перевіряв адресу його реєстрації.

## Виправлено
- `scripts/stamp-build.mjs` тепер автоматично оновлює `/admin/sw.js?v=BUILD` у `assets/admin-v250.js`.
- `scripts/check-build.mjs` тепер перевіряє, що реєстрація Service Worker присутня рівно один раз і відповідає поточному build.
- Версію піднято послідовно до `3.0.6`, build `3006`.
- Усі HTML-ресурси, `admin/sw.js`, `assets/admin-v250.js`, `assets/vacleaner-core.js` і згенеровані локальні Edge Function config-файли проштамповані версією `3006` / `3.0.6`.

## Що не змінювалося
- Фінансова формула.
- Суми залогу.
- Каталог і ціни.
- Логіка передоплати.
- Логіка хімії.
- Supabase production.
- Edge Functions у production.
- GitHub Pages і GitHub Actions не запускалися з цього середовища.

### Збірка
- `npm run stamp` — успішно.
- Повторний `npm run stamp` — байтово ідемпотентний, файли не змінилися повторно.
- `npm run check` — успішно.
- `npm run build` — успішно.
- Pages artifact: 190 файлів, 4856 KiB.
- Ключові файли в `dist` присутні.
- Ключові source/dist файли мають однакові SHA-256.
- Застарілих `?v=3001`, `?v=3005` і `vacleaner-manager-3005` у робочих файлах не знайдено.

### JavaScript і PWA
- Синтаксис локальних JavaScript-файлів перевірено через `node --check` усередині `npm run check`.
- Runtime адмінки викликає `/admin/sw.js?v=3006` зі scope `/admin/`.
- Кеш Service Worker: `vacleaner-manager-3006`.
- Ресурси в `admin/sw.js` мають `?v=3006`.

### UI smoke test у Chromium
Тест виконаний на локально зібраних assets у headless Chromium. Запити до Supabase були замокані тестовими відповідями; production Supabase не викликався і не змінювався.

Результат: **35 із 35 перевірок пройдено**.

Перевірено:
- desktop: 8 розділів у лівому меню;
- desktop: кнопка «Ще» прихована;
- desktop: кнопка «Нове бронювання» видима;
- mobile: нижня навігація має 5 правильних пунктів;
- mobile: меню «Ще» містить Клієнти, Аналітику, Хімію та Налаштування;
- mobile: перехід між вкладками повертає контент нагору;
- відсутність горизонтального overflow на 390 px;
- модалка нового бронювання на desktop і mobile не виходить за viewport;
- footer модалок видимий;
- мінімальна висота кнопок у mobile-модалці — 44 px;
- модалка видачі відкривається;
- поле фактичного залогу має `type="text"`, без браузерних числових стрілок;
- сума залогу стартує з 1000 грн і змінюється кнопкою на 1500 грн;
- модалка фінального розрахунку відкривається;
- нуль пакетиків показується порожнім полем;

- плюс змінює `1` на `2`;
- мінус із `2` до нуля повертає порожнє поле;
- JavaScript page errors у desktop і mobile тестах відсутні.

- Реальне оновлення вже встановленої PWA після деплою на `vacleaner.pp.ua` не перевірялося.
- Реальні записи, авторизація та Edge Functions Supabase не викликалися.
