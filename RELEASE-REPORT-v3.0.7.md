## Що виправлено

### 1. Безпечне відображення даних в адмінці

- Додано екранування тексту клієнтів, адрес, Telegram, приміток, назв і даних аудиту перед вставленням у HTML.
- Динамічні модалки та деталі проходять санітизацію.
- Збережені в базі рядки не можуть створити `script`, `iframe`, небезпечний атрибут або виконати JavaScript у протестованих сценаріях.
- До сторінки адмінки додано Content Security Policy з обмеженням джерел script, connect, object, base та form action.

### 2. Адмінська сесія

- Access token і refresh token більше не зберігаються постійно в `localStorage`.
- Сесія зберігається у `sessionStorage` і завершується після закриття браузерної сесії.
- Старий запис у `localStorage`, якщо він існує, одноразово переноситься та видаляється.

### 3. Серверний фінальний взаєморозрахунок

Edge Function тепер самостійно обчислює:

`передоплата + фактично отриманий залог − оренда − доставка − додаткові засоби − платна хімія`.

Frontend передає лише факти: фактичний залог, його отримання, використані пакетики, відмітку в сторіс і підтвердження фактичного повернення або доплати.

- `refundAmount` і `dueAmount` не використовуються як джерело істини для нової v3.0.7.
- Backend повторно читає бронювання з бази та обчислює баланс із актуальних даних.
- Завершення оренди, фінальний settlement і статус `completed` записуються одним серверним сценарієм.
- Доплата вважається отриманою лише після підтвердження менеджером.
- Повернення вважається виконаним лише після підтвердження менеджером.

### 4. Сумісність із кешованою PWA v3.0.6

Стара PWA могла ще певний час залишатися в кеші телефону та надсилати попередній формат із `refundAmount` і `dueAmount`.

Production-функція v10 підтримує цей формат лише як перехідний:

- суми заново обчислюються сервером;
- старі значення використовуються лише для точного порівняння;
- при відмінності повертається `settlement_mismatch` і бронювання не закривається;
- пряме збереження клієнтських сум відсутнє.

### 5. Хімія

- Для бронювань із Puzzi максимум — 8 пакетиків.
- Для техніки без Puzzi кількість примусово дорівнює нулю.
- При відмітці перші два фактично використані пакетики безкоштовні.
- Поле порожнє при нулі.
- Введення `1` залишається `1`.
- Плюс і мінус працюють від нуля.
- Значення обмежується діапазоном 0–8 на frontend і backend.

### 6. Додаткові засоби

Серверний розрахунок підтримує обидва формати історичних даних:

- `extras.selected_items` для адмінських бронювань;
- `extras.items` для заявок із публічного сайту.

Службові позиції `carpet_chemistry_kit` та `story_mention_bonus` не додаються до платної суми. Це закриває ризик втрати вартості додаткових засобів під час фінального перерахунку публічної заявки.

### 7. Публічні фінансові тексти

У публічній формі приведено до затвердженого формулювання:

- заголовок `Що потрібно для оформлення`;
- передоплата входить у фінальний взаєморозрахунок;
- новий клієнт надсилає документ менеджеру приватно;
- повторному клієнту повторне надсилання не потрібне;
- у правому підсумку один рядок `Поворотний залог — [сума] грн` і пояснення `Сплачується під час отримання техніки.`

Видалено заборонені формулювання про базову суму залогу, окреме повернення залогу та оплату оренди при видачі.

### 8. Слоти

- вечір: `17:30–20:00`.
