# VAcleaner v3.0.9 — OPERATIONS UX

Статус: release candidate. Не називати фінальним до перевірки після GitHub Pages deployment.

База релізу: повна збірка VAcleaner v3.0.8 — TRUSTED DEVICE SESSION.

## Мета релізу

Підвищити швидкість щоденної роботи менеджера без зміни фінансової логіки, каталогу, Supabase-схеми або Edge Functions.

## Виконані зміни

### 1. Операційна панель

На початку розділу «Бронювання» додано чотири клікабельні показники:

- нові заявки;
- очікують оплату;
- видачі сьогодні;
- повернення сьогодні або прострочені події.

Натискання одразу відкриває потрібний фільтр або розклад найближчих подій.

### 2. Терміновість подій

Бронювання отримали контекстні мітки:

- «Видача сьогодні»;
- «Видача завтра»;
- «Повернення сьогодні»;
- «Повернення завтра»;
- «Повернення прострочено»;
- майбутня подія через N днів.

Прострочені бронювання візуально виділяються, але статус і фінансові дані не змінюються автоматично.

### 3. Найближчі події

Додані фільтри:

- усі;
- сьогодні;
- прострочені.

Дні «сьогодні», «завтра» та прострочені дні мають окреме візуальне маркування.

### 4. Ієрархія дій

Головна дія тепер показується першою:

- опрацювати заявку;
- видати техніку;
- прийняти повернення;
- переглянути фінальний розрахунок.

На mobile головна кнопка займає повний рядок. Другорядні дії залишилися доступними, але менше конкурують із головною.

### 5. Пошук

- пошук охоплює код бронювання, ім’я, телефон, Telegram, техніку та адресу;
- додана кнопка очищення;
- клавіша `/` фокусує пошук на desktop;
- пошук із будь-якого розділу автоматично відкриває «Бронювання»;
- показується кількість знайдених результатів;
- порожній результат має зрозумілу кнопку скидання.

### 6. Loading, error та offline UX

- під час завантаження показуються skeleton-картки;
- збій мережі більше не викидає менеджера на логін;
- сесія залишається збереженою;
- показується зрозумілий екран із повторною спробою;
- після відновлення інтернету дані оновлюються автоматично;
- на desktop доданий індикатор online/offline.

### 7. Mobile/PWA

- операційні картки та фільтри мають горизонтальний контрольований скрол;
- основні tap-зони не менші за 44 px;
- нижня навігація лишилася з п’яти пунктів;
- «Ще» відкриває Клієнти, Аналітику, Хімію та Налаштування;
- після переходу між розділами контент повертається нагору;
- модалки залишаються в межах viewport, footer видимий.

## Перевірки

Фактично виконано:

- `node --check assets/admin-v250.js` — успішно;
- `npm run stamp` — успішно;
- `npm run check` — успішно, 226 file checks;
- `npm run build` — успішно;
- повторний `npm run check` після build — успішно;
- `dist` — 191 файл, 4878 KiB;
- фінансові тести — 15/15;
- тести сесії — 4/4;
- UX static tests — 8/8;
- browser UI smoke — 30/30.

Browser smoke перевірив:

- усі 8 desktop-розділів;
- відсутність «Ще» на desktop;
- п’ять пунктів нижньої навігації mobile;
- 4 розділи в mobile «Ще»;
- операційну панель;
- пошук, очищення та `/` shortcut;
- фільтри статусів і найближчих подій;
- повернення scroll нагору;
- tap-зони;
- desktop/mobile bounds модалки;
- видимість footer;
- error/retry state;
- збереження входу при мережевій помилці.

Тест виконувався в Chromium із контрольованими mock-відповідями Supabase. Це не замінює live-тест після GitHub Pages deployment.

## Що не змінювалося

- фінансова формула;
- залогові суми;
- тарифи;
- каталог;
- база Supabase;
- RLS;
- SQL-міграції;
- Edge Functions;
- production-функція `vacleaner-admin-bookings-v3` v10.

## Після deployment

Потрібно вручну перевірити на реальному домені:

1. вхід у встановлену PWA і повторне відкриття без нового логіну;
2. нову заявку та пошук;
3. видачу із фактичним залогом;
4. повернення з хімією та фінальним розрахунком;
5. offline/retry після короткого вимкнення мережі;
6. оновлення Service Worker до build 3009.
